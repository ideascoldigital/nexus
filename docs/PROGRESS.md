- **2026-08-13** — Nexux gets a way in that is not the dashboard: the MCP control surface (D-62, `specs/21`). A local Claude — or any other system — can now list projects, ask what a run is doing, send a task, and launch or power a sandbox, over MCP. Three phases on one branch. **Tokens first**, because nothing else was safe to build before them: the app had never had an auth layer at all (Telegram is outbound-only, there is no middleware, no session), and one of the tools spends money. `ApiToken` stores only the sha-256 of a `nxs_`-prefixed 32-byte value, shown once at creation and unrecoverable after — unsalted on purpose, since a 256-bit random value has no dictionary to defend against and a salt would only cost the unique-index lookup. Unknown, malformed and revoked tokens share one bare 401; revocation is a timestamp, not a delete, because after a leak the record of when a token was made and last used is the thing worth keeping. Scopes split by blast radius rather than by route, so `sandboxes:write` (real Civo/AWS, real money) is separable from `tasks:write`. **Then the tool layer**, `@nexux/mcp`, importing nothing but node builtins — no Prisma, no Next, no third-party dep — behind a `NexuxContext` the host implements. That is what makes it publishable later *and* what makes the scope check mean anything: a tool that could reach the Prisma client could reach every table whatever its scope said. Each tool carries its own scope rather than sitting in a side table a new tool can be forgotten from. **Then the transport**, `/api/mcp` on the SDK's web-standard streamable HTTP (Next speaks Web `Request`/`Response`; the Node variant wants `IncomingMessage`), stateless so every request re-verifies its token instead of trading it for a session — a lookup per call, in exchange for revocation taking effect immediately. An out-of-scope tool answers exactly as an unknown one, and `tools/list` is filtered too, so a narrow token is never told what a broader one could do. Since an MCP request carries a token and not a cookie there is no active workspace to read, so the surface answers for the default one, with the boundary enforced by id as well as by list. 47 new tests; verified live against the dev server — 401 without a token, a read-only token seeing five tools and none of the three writes, real projects and activity returned, `launch_sandbox` refused with nothing provisioned. Answering a blocked run is deliberately left out: `needsInput` belongs to the dev console, and out-of-band delivery into an interactive session needs its own spec. CI's typecheck also gains `--continue`, closing the gap that hid the failure below.

The width is a per-machine preference, so it goes in `localStorage` in pixels (a form's comfortable width doesn't scale with the monitor), via a new `useResizablePanel` hook and an optional `resizeHandle` on `SheetContent` — drag or arrow keys, `Home` to reset. Unsaved-ness is derived, not stored: `SetupEditor` diffs a `JSON.stringify` of `{config, mcpJson, repoSetups}` against a snapshot taken on load and reset after each save, and reports it up so the sheet can `cancel()` the dismissal and confirm. Only `outside-press`/`escape-key` are intercepted — the X and the footer buttons still close on demand. URL persistence is opt-in (`persistStepInUrl`) so the Run dialog, which mounts the same sheet transiently, doesn't fight for the same params. Two bugs found by testing rather than reading: `?sandboxStep=` must *survive* closing, since the editor stays mounted behind the closing animation and deleting it made reopening look like a reset; and clamping the stored width against an unmeasured `innerWidth === 0` collapsed it to the minimum, so a resized drawer reopened tiny (`clampPanelWidth` is exported and unit-tested for it). Verified in the browser: refresh restoring a non-default step, a drag persisting across a reload, and both dismissal paths confirming with "Keep editing" preserving the edit.

- **2026-08-02** — sandbox terminals stopped being a bare prompt (D-27). Opening a shell into a sandbox told you nothing: not which repos were checked out, not where they lived, not which command booted them, not what was already running — that all lived in the host's database, reachable from the Processes panel and nowhere else. Bootstrap now writes `/opt/nexux/nexux.json` (repos + one entry per startable process: key, alias, command, cwd, port) and `/etc/profile.d/nexux-cli.sh`, giving every login shell an ASCII banner and a `nexus` command: `nexus` for the dashboard, `nexus start|stop|restart <alias>` (or `all`), `nexus logs <alias> [-f]`, `nexus cd <project>`, `nexus status`, `nexus info`, `nexus help`, with tab completion over the aliases. A manifest rather than a callback to the host API — the container has no route to the dashboard, and a snapshot keeps working when the host is down. Start/stop reuse `sandbox-process-manager.ts`'s exact `/tmp/nexux-proc-<key>.{sh,pid,log}` paths and its setsid + kill-by-recorded-PID discipline, so a process started in the terminal is the same one the UI lists and stops. Being a snapshot, it goes stale on a canvas edit: `nexus info` prints its write date and "Sync terminal CLI" (POST `…/sandboxes/<id>/cli`) rewrites it from the current plans — manual, because a canvas save should not silently exec into a running box. The banner is guarded on an interactive shell, since `execRemote` sources profile.d through `bash -lc` and the host regexes that stdout for `PID:` markers; parsing uses `python3`, which `ubuntu:22.04` ships and `jq` is not. Verified end to end in a real `ubuntu:22.04` container: pid == pgid on start, zero orphans after stop, `bash -lc` output banner-free.

- **2026-07-31** — the sandbox log panel shows more than bootstrap. A sandbox writes four logs the UI could not reach: the live-preview app (`/tmp/nexux-app.log` — the `pnpm dev` output), the cloudflared tunnel, dockerd, and the stack services (which run under the sandbox's *inner* dockerd, so `docker logs` from the host cannot see them — compose has to be driven inside the container). - **2026-07-31** — a multi-line env var no longer truncates the repo `.env`, and a container that dies is noticed. `renderRepoSection` wrote `KEY=${value}` raw into a heredoc: a value with newlines (a service-account JSON whose `private_key` holds a PEM, the shape the Google console hands you) turned every line after the first into a stray assignment, and a value containing the terminator ended the file early — losing every var below it. Values are now **single**-quoted onto one physical line: double quotes would force escaping the backslashes a service-account JSON already carries, and `dotenv` / `node --env-file` hand back `{\"type\"...}`, which no longer parses. Verified byte-identical through `node --env-file`, the `dotenv` package, `python-dotenv` and `set -a && . ./.env`. Note `export $(cat .env | xargs)` cannot load *any* value with spaces — xargs re-parses quotes and strips backslashes; the supported loader is `set -a && . ./.env`. Separately, the `status` column was only written when *we* paused/resumed/destroyed, so a container killed by OOM or a Docker restart left the row reading "running" forever: the UI offered Live preview and no Resume while every real action failed with "Sandbox is not running". `GET /sandboxes` now reconciles local rows against `docker inspect` (downgrade-only, and never when Docker itself is unreachable), the list polls every 15s so the flip needs no manual refresh, and Resume is in the row menu too.

- **2026-08-04** — sandbox SSH stopped being a race against apt, and copy buttons survived plain http.
